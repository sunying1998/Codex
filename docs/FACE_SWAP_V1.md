# 第一版：保留原片内容，仅替换脸部

## 已确认的范围

私人试用，效果优先。首轮使用 5–10 秒、单个主要人物、单镜头的视频和一张清晰的目标人物照片。网站仍可保存多张照片，但一次换脸任务只选择一张；这不是批量人物替换或全片 MV 自动处理。

只改变目标脸部身份，目标是保持原片的头发、身体、服装、背景、镜头运动、人物动作、表情、口型和音轨内容。唱歌时使用原有歌曲和人声，不重新生成声音。保留原片和照片，处理结果独立保存，支持原片与结果对比、再次生成和下载。

首版不提供换头、换装、全身或多人替换。下一步可加入服装修改，但要有单独的任务输入、服装区域约束及质量评测，不能让换脸服务替代这些能力。

## 当前状态

上传、解析、片段保存、异步本地导出和 Git 更新已具备。服务端 `ReplacementProvider` 是待实现的接入契约，首版输入收窄为 `mode: face` 和一个 `referenceAssetId`。当前没有真实换脸供应商、供应商凭据、远端任务或可执行的换脸接口；能力接口仍返回 `available: false`，界面入口保持禁用，普通导出仍保留原人物。

## 模型与服务选择

优先评测专用视频换脸服务。需要原视频和照片的输入、稳定的同一人脸跟踪、表情和口型保留、遮挡处理及异步任务查询。首版不以整个人物重生成、动作迁移或文生视频的结果冒充面部替换。

接入前确认实际 API 文档、视频时长与尺寸限制、文件上传方式、模型版本、任务状态、取消能力、计费口径及结果保存时限。尚未核实这些内容的平台只列为候选，不指定未经证实的接口地址、模型 ID 或费用，也不因为平台支持“视频生成”就宣称它支持该需求。未实测的换脸质量不写作已实现能力。

先用相同的正脸、侧脸/转头、唱歌及手部遮挡短片比较结果，再决定第一家供应商。当前没有依据宣称某一家服务已通过评测。未来收费使用前，再核对服务和依赖模型的商业使用条款。

## 处理与接入设计

1. 网站保存任务输入快照：项目、源视频、入出点、一张参考照片、目标人物及模型版本。先限制单个主要人物，不能在遇到多人时自动选择另一张脸。
2. Worker 在本机准备视频片段并独立保留对应音频。临时文件放在私有数据目录，原文件保持完整。
3. 通过服务端 API 上传所选片段和照片。云端服务不能读取本机的 `127.0.0.1` 素材地址，应使用服务提供的文件上传能力或有时效的访问地址。所选素材会传给供应商；密钥仅放在本机服务端配置，不传给浏览器或提交到 Git。
4. 服务如支持脸部图层/掩膜，优先将脸部结果合成回原帧。只返回整段视频的服务，需要验证脸外区域是否改变，必要时增加本地跟踪、掩膜与合成步骤；未验证前不承诺背景等区域完全不变。
5. 远端任务编号和状态持久化，由 Worker 轮询，不依赖公网回调。重启后查询原任务；提交响应不明确时不得直接重提收费任务。重复点击应返回原任务。
6. 下载并校验结果，核对时长、时间轴、画面尺寸、帧率与音画同步，再合入原音轨。保留原音轨内容；必要的重新封装或编码不代表输出文件字节完全相同。
7. 生成独立结果，提供对比与下载。无法确认目标人物、出现明显身份闪变、结果为空或模型未执行时，显示实际失败原因，不能把原片作为“换脸成功”的结果。

## 样片验收

| 检查项       | 通过目标                                                                       |
| ------------ | ------------------------------------------------------------------------------ |
| 人物身份     | 接近参考人物，连续帧与转头时稳定，无另一人物串入                               |
| 表情与口型   | 保留原片的表情、张嘴及唱歌节奏，避免嘴部糊化和错位                             |
| 脸部融合     | 肤色、光影、边缘自然，无明显接缝和逐帧闪烁                                     |
| 遮挡         | 头发、手和其他前景遮挡关系合理，不把脸绘制到遮挡物上                           |
| 原片内容     | 脸外的头发、身体、衣服、背景及镜头运动保持稳定，不接受整个人物重生成造成的变化 |
| 时间轴和声音 | 对应片段时长正确，原歌曲及人声内容保留，音画同步                               |
| 任务与版本   | 原片可恢复、结果独立保存、失败可诊断，重启不会盲目创建重复收费任务             |

编码会影响像素值，背景保留与音轨保留不表示导出 MP4 与原文件逐字节相同。最终效果需要真实样片和用户确认，接口成功或开发测试通过不能代替视觉验收。

## 实施顺序

先锁定上述范围与服务能力要求，再取得可验证的专用换脸 API 文档并完成少量样片测试；选定服务后，增加真实换脸任务、数据库状态、轮询恢复、结果校验和前端对比。用户在自己的电脑配置最终选定服务的密钥，通过项目现有的 `Update-Yingke.cmd` 获取代码。MCP 以后复用这些受认证的任务接口。

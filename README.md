# 映刻 YINGKE

面向个人内测的 AI 视频创作工作台。先验证素材、项目、剪辑与异步任务的完整流程，后续接入真实人物替换模型，再逐步面向中国大陆开放。

## 当前可用

- 首次创建唯一工作室账号，密码哈希保存，使用 HttpOnly 会话登录。
- 项目创建、搜索、重命名、保存、恢复和删除。
- 视频流式上传、后台解析、缩略图生成、拖动播放。
- 人物参考照片上传、解析和删除，每项目最多 8 张。
- 设置片段入点、出点，生成独立 H.264 / AAC MP4，保留多个导出版本。
- 持久化任务队列、进度、取消、重复提交去重、失败提示、中断恢复。
- 中文桌面与手机界面、任务中心、素材用量。

**人物替换尚未接入。现有导出保留原人物；模型接口是服务端扩展契约，不会返回模拟生成结果。MCP、公众注册、支付、邮件找回和专业多轨剪辑尚未实现。**

## 启动

Windows 个人试用推荐使用 Git 托管入口。已有解压版用户先关闭旧启动窗口，运行一次性 Git 接入器；它会备份旧代码，保留账号、素材和本机配置。首次接入完成后，不再需要反复下载、解压修复包。

| 双击入口              | 作用                                                              |
| --------------------- | ----------------------------------------------------------------- |
| `Start-Yingke.cmd`    | 安装缺失的项目依赖、按需构建、后台启动网页与 Worker，并打开浏览器 |
| `Update-Yingke.cmd`   | 从 `origin/main` 安全更新，备份、重建并重启服务                   |
| `Stop-Yingke.cmd`     | 停止本工具启动的本项目服务                                        |
| `Status-Yingke.cmd`   | 检查运行状态                                                      |
| `Diagnose-Yingke.cmd` | 生成本机图片诊断报告                                              |

启动完成后可以关闭命令窗口，服务继续运行；停止时使用 `Stop-Yingke.cmd`。第一次接入前的旧启动器仍需要手动关闭一次。详细步骤、数据保护与故障处理见 [Git 同步说明](docs/GIT_SYNC.md)。

新建空目录也可直接克隆，再使用项目内的启动入口：

```bash
git clone https://github.com/sunying1998/Codex.git yingke-studio
cd yingke-studio
npm run local:start
```

下面的 `npm run dev` 是开发模式，与上面的托管运行模式择一使用。

要求 Node.js 24+、npm、FFmpeg / ffprobe（包含 libx264 与 AAC 编码器）。当前云环境已具备。

在现有检出目录工作；云任务本身已隔离，无需额外创建 Git worktree。

```bash
cd /workspace/Codex
npm ci
npm run dev
```

`dev` 同时启动网页与后台 Worker，默认端口 3000。首次访问时在页面创建账号，不存在默认密码。**首次初始化应在受信网络内完成，再配置外部访问。** 请妥善保管账号与密码，当前未接入邮件找回。

生产模式需要两个持续运行的进程：

```bash
npm run build
npm start
```

另一个终端，使用同一目录、同一环境变量：

```bash
cd /workspace/Codex
npm run worker
```

`npm start` 仅启动网页。Worker 不在线时任务保留在队列，恢复后继续处理。SIGTERM / Ctrl+C 会把未完成任务重新排队；异常退出的 Worker 租约最多 30 秒过期。当前只允许一个 Worker。

## 配置与持久化

可复制 `.env.example` 为 `.env.local` 后填写非敏感运行配置：

| 变量              | 用途                                                                                       |
| ----------------- | ------------------------------------------------------------------------------------------ |
| `YINGKE_DATA_DIR` | 持久化目录的绝对路径，默认仓库内 `.data/`；网页和 Worker 必须一致                          |
| `PORT`            | 网页端口，默认 `3000`                                                                      |
| `APP_ORIGIN`      | 反向代理后的精确外部源，例如 `https://studio.example.com`；HTTPS 时启用 Secure 会话 cookie |
| `CHROMIUM_PATH`   | 浏览器测试所用 Chromium 路径，可选                                                         |

`.data/studio.sqlite` 保存账号、会话、项目、任务，`.data/media/` 保存原素材、缩略图和导出文件。二者必须存放在持久卷中，不能放到公开静态目录；已从 Git 排除。不要提交素材、账号数据库或密钥。

内测限制：单个视频最大 512 MB、最长 10 分钟、最长边 4096；参考照片每张最大 15 MB、最长边 8192、总像素不超过 32 MP。源素材总额度 10 GB、最多 100 个项目、同时最多 10 个导出待处理任务。导出保留原分辨率，奇数尺寸会向下对齐至偶数；重新编码会产生一定损失。

MOV、MKV、WebM 中部分编码不能在浏览器直接播放，可尝试导出 MP4 后下载查看。原始视频画面与原音频一起裁剪，不修改人物外貌。

## 验证

```bash
npm run typecheck
npm test
npm run build
npm run test:smoke
npm run test:browser
npm run test:sync
npm run test:managed
npm run format:check
```

- 单元测试覆盖密码校验、跨站来源校验、片段时间、文件范围请求和路径边界。
- Smoke 测试使用独立临时数据库和生成的真实视频，覆盖登录、无效文件、上传、照片、解析、Range、保存冲突、去重、取消、重启继续、实际音视频导出、下载和删除。
- 浏览器测试使用 Chromium，覆盖建号、创建、上传、播放、片段保存、刷新恢复、导出、搜索和手机导航；截图保存在被忽略的 `test-results/`。
- Git 测试覆盖旧文件夹接入、源码备份、快进更新、本地修改与分叉保护、依赖缓存、数据保留和失败重试。托管运行测试覆盖进程控制认证、真实视频处理、停止与中断恢复。
- 测试账号、素材与进程会在结束时清理，不修改正常工作室的数据。

浏览器测试优先使用 `CHROMIUM_PATH`，其次 `/usr/bin/chromium`；没有系统浏览器时可运行 `npx playwright install chromium`。云环境 npm 缓存不可写时，可给 npm 命令加 `--cache /workspace/.npm-cache`。

## 备份与恢复

停止网页与 Worker 后，将**整个持久化目录**复制或归档到单独的安全位置，包括 SQLite、WAL / SHM（若存在）、media。不要只复制数据库或只备份素材。

恢复时保持两个进程停止，将备份还原到独立目录，让 `YINGKE_DATA_DIR` 指向该目录，再启动网页与 Worker。先检查登录、项目列表、原片播放和一次片段导出。备份包含账号及私人素材，应限制访问并定期验证恢复。不要用复制正在写入的 SQLite 文件代替一致性备份。

## 边界与下一阶段

当前是单机个人内测架构，使用本地 SQLite 与本地文件，不适合直接横向扩展或部署到无持久磁盘的 Serverless 环境。上线公网前需要 HTTPS、持久卷、进程托管、反向代理上传大小 / 超时配置以及磁盘监控。

下一阶段先以短片评测真实模型的身份一致性、转头、口型、遮挡和时间稳定性。后续公众版本再迁移 PostgreSQL / 对象存储 / 分布式任务，补齐注册、账号恢复、存储与计算额度、支付和退款、监控与数据管理，并按大陆部署方案落实备案等要求。

详细范围见 [产品规划](docs/PRODUCT.md)，接口和运行方式见 [技术说明](docs/ARCHITECTURE.md)。
